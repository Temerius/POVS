## 🔧 Необходимые изменения в конфигурации проекта

### 1. Добавление файлов в проект

В вашем IDE (STM32CubeIDE, Keil, и т.д.) необходимо добавить следующие файлы в проект:

- `Core/Src/lcd_i2c.c` - драйвер LCD дисплея
- `Core/Inc/lcd_i2c.h` - заголовочный файл LCD

### 2. Настройка USART3 для приема команд

Убедитесь, что USART3 настроен следующим образом:

- **Baud Rate**: 115200
- **Word Length**: 8 bits
- **Stop Bits**: 1
- **Parity**: None
- **Mode**: TX_RX
- **DMA для RX**: Включен (DMA1_Channel3)
- **DMA для TX**: Включен (DMA1_Channel2)

### 3. Настройка прерываний

Убедитесь, что включены следующие прерывания:

- **USART3_IRQn** - для приема команд
- **DMA1_Channel2_IRQn** - для передачи через USART3
- **DMA1_Channel3_IRQn** - для приема через USART3

### 4. Изменение режима TIM2

В файле `main.c` уже изменен режим TIM2 с `TIM_OCMODE_TOGGLE` на `TIM_OCMODE_PWM1` с `Pulse = 816`.

Если вы используете STM32CubeMX, убедитесь, что:
- TIM2 Channel 2 настроен в режиме **PWM Generation CH2**
- Pulse = 816
- Period = 1632

### 5. Проверка DMA для ADC

Убедитесь, что DMA для ADC1 настроен:
- **DMA1_Channel1** для ADC1
- Режим: Circular
- Data Width: Half Word

## 📡 Протокол связи Bluetooth

### Команды от GUI к плате:

- `S` (или `S\r\n`) - Начать запись
- `T` (или `T\r\n`) - Остановить запись

### Ответы от платы к GUI:

- `START_OK\r\n` - Запись начата
- `STOP_OK\r\n` - Запись остановлена
- `AUDIO:XXXX,XXXX,XXXX,...\r\n` - Аудио данные (16-битные значения через запятую)

## 🖥️ Запуск GUI

1. Откройте файл `gui/index.html` в браузере Chrome, Edge или Opera (поддержка Web Serial API)
2. Выберите COM порты для отправки и приема
3. Нажмите "Подключиться"
4. Нажмите "Начать запись" для старта
5. Нажмите "Остановить" для завершения
6. Воспроизведите или скачайте запись

## ⚠️ Важные замечания

1. **Два COM порта**: Для работы нужны два разных COM порта:
   - Один для отправки команд (TX)
   - Один для приема данных (RX)

2. **Скорость передачи**: Если возникают проблемы с потерей данных, можно:
   - Уменьшить частоту отправки данных в `main.c` (отправлять не каждый буфер)
   - Увеличить размер буфера в GUI

3. **Формат данных**: Аудио данные отправляются в формате:
   ```
   AUDIO:value1,value2,value3,...\r\n
   ```
   где каждое значение - это 16-битное число от ADC (0-4095 для 12-битного ADC)

4. **Частота дискретизации**: В коде используется 44.1 kHz. Это должно соответствовать настройке TIM2.

## 📝 Дополнительные настройки (опционально)

### Изменение частоты отправки данных

В функции `main()` в цикле `while(1)` можно изменить частоту отправки данных:

```c
// Отправлять данные не каждый раз, а через раз
static uint8_t skip_counter = 0;
if(bt_recording && (skip_counter++ % 2 == 0)) {
    Send_Audio_Data_Bluetooth(current_buffer, FFT_SIZE);
}
```

### Увеличение размера буфера передачи

В функции `Send_Audio_Data_Bluetooth()` можно увеличить размер буфера `bt_tx_buffer` если нужно отправлять больше данных за раз.

## 🐛 Решение проблем

### Проблема: Данные не приходят в GUI
- Проверьте, что выбран правильный COM порт для приема
- Проверьте скорость передачи (115200)
- Проверьте, что прерывания USART3 включены

### Проблема: Команды не отправляются
- Проверьте, что выбран правильный COM порт для отправки
- Проверьте, что прерывания USART3 включены
- Проверьте, что `HAL_UART_Receive_IT` вызван в `main()`

### Проблема: Запись не начинается
- Проверьте, что команда `S` отправляется правильно
- Проверьте обработчик `HAL_UART_RxCpltCallback` для USART3
- Проверьте, что флаг `bt_recording` устанавливается
